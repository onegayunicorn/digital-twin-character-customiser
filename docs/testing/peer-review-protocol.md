# Peer-Review Protocol (Real Review, Not Role-Play)

**Owner:** Peer-Review Agent · **Applies to:** all scientific claims and manuscripts.
"Historical minds" simulations in the source documents are *illustrative*, never a
substitute for human reviewers.

## 1. Principles

1. Reviewers are real physicists/domain experts; the protocol removes friction from
   their job (reproducibility, transparency).
2. Negative results are included — credibility depends on it (the planetary 1/r
   falsification ships with every manuscript).
3. Every claim in a manuscript maps to [`../theory/04-claims-register.md`](../theory/04-claims-register.md).

## 2. Submission checklist

- [ ] Manuscript (LaTeX/arXiv style) with abstract, intro, methods, results, discussion.
- [ ] Every section cites claim status (VERIFIED/SIMULATED/HYPOTHESIS).
- [ ] Claims register updated with all new claims; statuses defensible.
- [ ] Reproducibility pack: Dockerfile + pinned `requirements.txt` + entry scripts.
- [ ] Fresh-container run passes (L2 gate) with logs captured.
- [ ] Figures regenerated by the same scripts that produced the numbers.
- [ ] Data files archived to public bucket (`dev-ipp-docs` or `dev-ipp-sims`).
- [ ] Author checklist signed (no unverified claims; conflicts declared).

## 3. Target venues

| Artifact | Venue | Notes |
|---|---|---|
| Rotation-curve pressure model + falsification analysis | arXiv physics.gen-ph / space-ph, then journal (MNRAS/PRD route if data supports) | Start preprint; journal after community feedback |
| IPS validation data (post phase-0/1) | Sensors / Optics Express class | Requires HIL data |
| VRmemories ethics & methodology | CHI / CSCW / HCI venues | Requires pilot data |

## 4. Review workflow

1. Preprint → arXiv (or preprint server) → community feedback window (≥2 weeks).
2. Recruit 2-3 domain reviewers with clear review briefs (methods, reproducibility,
   claims-register check).
3. Collect reviews → revision log (response-to-reviewers doc) → revise → re-submit.
4. On acceptance/publication: update claims register (HYPOTHESIS → VERIFIED where
   warranted) and mark the artifact in `docs/theory/01-theory-consolidated.md`.

## 5. Reviewer brief (template)

> You are reviewing [manuscript] for [venue]. Please verify: (1) methods match the
> provided code exactly (Docker: [ref]); (2) each claim's status in the claims register;
> (3) whether negative results are reported; (4) whether the rotation-curve model is
> physically defensible. We request a verdict on: reproducibility, scientific soundness,
> and significance. Conflicts of interest: [declare].

## 6. Escalation rules

- If reviewers identify a modeling error → fix code + tests → re-run → revise (never
  patch numbers).
- If the falsification result is confirmed → update register, adjust theory framing
  (never hide it).
- If a claim cannot be defended → downgrade to HYPOTHESIS or remove from external
  materials.
